# BenHouse v0.4 — Visión

## Objetivo

BenHouse es una plataforma PropTech inmobiliaria diseñada para evolucionar desde el modelo tradicional de portal de anuncios hacia un ecosistema que ayude al usuario a descubrir, entender, decidir, gestionar y completar una operación inmobiliaria dentro de una experiencia coherente.

BenHouse v0.4 es el MVP técnico y visual destinado a validar esta visión con usuarios, agencias, clientes potenciales, inversores y colaboradores antes de una operación comercial real.

La prioridad de v0.4 no es incluir el máximo número de funcionalidades, sino demostrar una experiencia completa, coherente, competitiva y técnicamente sólida.

## Posicionamiento

BenHouse no debe percibirse como otro portal inmobiliario genérico.

Idealista y Fotocasa son referencias obligatorias en España y marcan el estándar mínimo esperado en:

- búsqueda;
- filtros;
- mapa;
- fichas de inmueble;
- favoritos;
- alertas;
- publicación;
- contacto;
- experiencia profesional.

BenHouse debe alcanzar un nivel competitivo en esas capacidades básicas, pero su diferenciación no puede depender exclusivamente de ellas.

La ventaja estratégica de BenHouse se construye mediante la integración de:

- búsqueda inmobiliaria;
- inteligencia de mercado;
- datos de demanda;
- comparables;
- confianza y verificación;
- visitas;
- ofertas y negociación;
- operaciones;
- documentación;
- contratos;
- firma;
- pagos;
- seguimiento posterior;
- CRM profesional conectado con la actividad real de la plataforma.

## Propuesta de valor

La experiencia debe responder progresivamente a cuatro preguntas:

1. **Descubrir**

   ¿Qué propiedades encajan con lo que busco?
2. **Entender**

   ¿Está bien de precio? ¿Cómo se comporta esta zona? ¿Existe demanda? ¿Qué propiedades son comparables?
3. **Decidir y actuar**

   ¿Quiero guardarla? ¿Quiero visitarla? ¿Quiero contactar? ¿Quiero hacer una oferta?
4. **Completar**

   ¿Qué pasos faltan para terminar la operación? ¿Qué documentación necesito? ¿Qué debo firmar? ¿Qué pagos están pendientes? ¿Cuál es el estado de la operación?

Toda funcionalidad de v0.4 debe contribuir claramente a una o varias de estas cuatro fases.

Si una funcionalidad no ayuda a descubrir, entender, decidir, actuar o completar una operación, debe cuestionarse su inclusión en v0.4.

## Journey principal

La experiencia central de BenHouse debe poder recorrer:

Inicio → Buscar → Resultados → Mapa → Zona → Propiedad → Intelligence → Visita → Oferta/Puja → Operación → Documentación → Contrato → Firma → Pago → Finalización → Historial

La plataforma debe sentirse como una experiencia continua.

Contratos, documentación, firma y pagos no deben aparecer como productos aislados o módulos técnicos independientes para el usuario.

## Diferenciación

BenHouse no debe competir únicamente mostrando más información.

Debe transformar información en contexto y acciones.

Un insight solo tiene valor si ayuda al usuario a tomar una decisión.

Ejemplo:

Propiedad → Comparables → Precio competitivo → Solicitar visita / Guardar / Hacer oferta

Intelligence no debe ser una página decorativa ni un conjunto de scores sin explicación.

Debe integrarse en la experiencia.

## Principios de producto

1. La vivienda y la fotografía son protagonistas.
2. La complejidad técnica debe permanecer oculta.
3. La inteligencia debe ser explicable.
4. La IA generativa no debe inventar métricas.
5. La confianza debe basarse en evidencias verificables.
6. Un usuario puede desempeñar distintas funciones dentro de una misma cuenta.
7. La experiencia debe ser continua, no una colección de módulos independientes.
8. La plataforma debe simplificar procesos complejos.
9. Las decisiones críticas pertenecen al backend.
10. Seguridad, privacidad, historial y trazabilidad son requisitos del producto, no añadidos posteriores.

## Filosofía visual

BenHouse debe transmitir:

- inmobiliario;
- premium;
- tecnológico;
- humano;
- claridad;
- confianza.

Principios visuales:

- fondo predominantemente blanco;
- verde y azul como colores funcionales principales;
- amarillo utilizado únicamente como acento;
- tipografía moderna, legible y con personalidad;
- iconografía minimalista;
- fotografía inmobiliaria profesional como elemento visual dominante;
- interfaces limpias;
- evitar dashboards genéricos;
- evitar exceso de tarjetas, puntuaciones, badges y elementos visuales compitiendo entre sí.

## Mercado inicial

BenHouse v0.4 está orientado inicialmente al mercado español.

La arquitectura debe permitir evolución internacional futura, pero v0.4 no debe introducir complejidad internacional innecesaria antes de validar el producto.

## Objetivo del MVP

v0.4 debe demostrar al menos dos historias completas.

### Usuario

Registro → búsqueda → mapa → Intelligence → favorito → alerta → visita → oferta → aceptación → operación → documentación → contrato → firma sandbox → pago sandbox → operación completada

### Profesional

Acceso profesional → cartera → demanda → Match → lead → visita → oferta → operación

Si estas historias no pueden completarse de forma coherente y estable, v0.4 no debe considerarse terminada.

## Qué significa éxito para v0.4

BenHouse v0.4 será satisfactoria cuando:

- la búsqueda y el mapa sean competitivos;
- las fichas transmitan calidad inmobiliaria;
- Intelligence ayude realmente a decidir;
- los flujos críticos estén conectados;
- las operaciones puedan recorrerse de extremo a extremo en sandbox;
- propietarios y profesionales reciban información útil;
- la plataforma sea visualmente coherente;
- el producto sea responsive;
- los permisos y estados estén protegidos;
- los tests críticos sean satisfactorios;
- el producto pueda demostrarse sin depender de explicaciones técnicas externas.

## Disciplina de alcance

v0.4 tiene alcance congelado.

Una nueva idea no se implementará automáticamente.

Clasificación:

- bug → corregir;
- vulnerabilidad → corregir;
- contradicción arquitectónica → corregir;
- requisito necesario para completar una funcionalidad ya aprobada → evaluar e integrar;
- mejora no crítica → backlog;
- nueva funcionalidad → backlog post-v0.4.

El objetivo es terminar, probar y lanzar v0.4, no ampliar indefinidamente su alcance.
